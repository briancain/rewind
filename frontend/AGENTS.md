## How this app is built

- **Next.js 16 App Router + React 19 + TypeScript + Tailwind v4.** Dark-first theme
  (neutral/red palette); light/dark via CSS variables + `components/ThemeToggle.tsx`.
- **Everything is a client component (`"use client"`).** There is **no** server-side data
  fetching, no Server Components data layer, and no server actions. Pages fetch on the client.
  → Most of the Next.js "breaking changes" warning above concerns server features we don't use,
    but still read the bundled docs before reaching for any new Next API.
- **API access goes through `lib/api.ts`.** Use `svc(service, path, options?)` — `service` is one
  of `identity | catalog | upload | streaming | social | search`, each a separate backend with its
  own base URL. It attaches the bearer token and parses JSON. Don't hand-roll `fetch`.
- **Per-service base URLs come from `NEXT_PUBLIC_*` env vars**, which Next inlines at **build
  time**. `deploy.sh` passes them as Docker `--build-arg`s (not runtime env) — if you add a new
  one, wire it in `docker/Dockerfile.frontend` + `deploy.sh`, not just at runtime.
- **Auth:** token in `localStorage`; use `useAuth()` / `useRequireAuth()` from `lib/auth.tsx`.
  `useRequireAuth()("do X")` returns false + prompts sign-in when logged out.

## Video playback (important gotcha)

- Playback lives in `components/VideoPlayer.tsx` — Media Chrome + `hls-video-element` (hls.js under
  the hood, native HLS on Safari). It serves CloudFront HLS `.m3u8` for public/unlisted videos and
  a presigned MP4 for private/legacy.
- These web components call `customElements.define` **on import**, which crashes SSR and jsdom.
  → Always load it via `next/dynamic(() => import("@/components/VideoPlayer"), { ssr: false })`,
    never import it directly into a normally-rendered tree.
- Optional props: `autoPlay` + `onEnded` (used by the surf "TV" page), `onWatched` (fires once
  after 5s → view count + history). The DOM wiring is extracted into `lib/player.ts` so it's
  unit-testable without rendering the web components.

## Testing conventions

- Unit tests live in `__tests__/` (ts-jest, jsdom). The codebase favors **pure-logic** tests:
  extract logic into `lib/*.ts` and test it directly, rather than rendering web-component-heavy
  UI. (`@testing-library/react` is installed if a real render is genuinely needed.)
- Mock backends by `jest.mock("@/lib/api")` and stubbing `svc` (see `__tests__/surf.test.ts`).

## Conventions / patterns

- Reuse shared bits: `lib/format.ts` (`formatDuration`, `timeAgo`), `components/Thumbnail.tsx`.
- `<img>` is used (with `// eslint-disable-next-line @next/next/no-img-element`) for presigned /
  dynamic S3+CloudFront URLs that `next/image` can't optimize. Match that pattern; don't fight the
  lint rule for these.
